# ApplyFlow

**Your internship search, minus the admin.**

ApplyFlow is an early-stage, student-focused concept for organizing internship opportunities, recruiter context, deadlines, and next actions. We are researching which workflow deserves an MVP rather than assuming students need another application tracker.

## Current stage
**Phase 1 — Exploratory discovery and low-fidelity prototype planning.** There is no production application, validated product-market fit, or measured outcome yet.

## Product documentation
- [Product brief](docs/product-brief.md) — vision, target students, hypotheses, initial scope, success metrics, and $0 constraints.
- [Customer discovery plan](docs/customer-discovery.md) — interview guide, recruiting approach, and validation milestones.
- [Reddit exploratory research](docs/reddit-discovery.md) — five public applicant case studies, contradictions, themes, and source links. This is secondary research, **not five interviews**.
- [Initial Figma prototype brief](docs/figma-prototype-brief.md) — proposed responsive screens, user flows, fictional demo data, and usability tasks. These screens have not yet been created in Figma.

## Working principles
- Validate an actual student problem before building features.
- Start with a $0, mobile-friendly web experience.
- Make application capture extremely fast and put user-defined next actions first.
- Avoid paid APIs, scraping, auto-applying, and unnecessary integrations in the first MVP.
- Protect research participants and user data; publish only anonymized/aggregate research.
- Label plans and hypotheses separately from real measured results.

## Next steps
1. Conduct five real student interviews to challenge the Reddit-derived hypotheses.
2. Build and test the proposed low-fidelity Figma screens.
3. Revise the product brief and write an evidence-based PRD.
4. Build a small MVP only once the key workflow is supported by evidence.
